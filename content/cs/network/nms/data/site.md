장비가 설치된 **장소** 하나(데이터센터·국사·지사·현장 중계소). [[cs/network/nms/data/topology/node|노드]]는 사이트에 속한다. NMS 지도에서 가장 작은 표시 단위이고, 사이트 안(장비·포트)은 토폴로지 화면에서 본다.

- **노드와 따로 두는 이유**: 장비 수백 대라도 좌표는 하나다. 위치 정보는 장소에 붙어야 장비마다 반복되지 않는다.
- **사람이 등록한다**: SNMP `sysLocation`은 자유 문자열이라 좌표·계층으로 못 쓴다. 그래서 NMS는 사이트를 기준 정보로 두고 장비가 사이트를 고르게 한다.

## 근거 문서 (공신력 순)

사이트만 정의한 단일 표준은 없다. 공식 표준 → 업계 명세 → 사실상 표준 순.

| 순위 | 문서 | 성격 | 가져오는 것 |
|---|---|---|---|
| 1 | ITU-T M.3100 | ITU-T 권고 | 장비는 한 지리적 위치에 있다(`locationName`) → 노드 : 사이트 = N : 0..1 |
| 2 | RFC 3418 SNMPv2-MIB | Internet Standard | `sysLocation`. 등록 힌트로만 |
| 3 | RFC 8299 L3SM · RFC 8466 L2SM | Proposed Standard | 주소 필드(`location` › `address`, `postal-code`) |
| 4 | RFC 9179 | Proposed Standard | 좌표(위도·경도, WGS 84, 기록 시각) |
| 5 | RFC 8345 | Proposed Standard | 사이트 없음 → 사이트는 그래프 밖 소속 정보, 회선은 링크에서 계산 |
| 6 | TM Forum TMF674 (+ TMF673) | 업계 명세 | 사이트(`GeographicSite`)와 주소 분리, 한 주소에 여러 사이트 |
| 7 | MEF 79 / 122 | 업계 명세 (TMF674 기반) | 사업자 간 사이트 조회 |
| 8 | NetBox | 사실상 표준 | Region > Site > Location(중첩) > Rack > Device 계층, 운영 상태 |
| 9 | 행정구역 코드 | 국가 코드 체계 | 지역(시·도, 시·군·구) 분류 |

- **용어 주의**: RFC 8299·8466의 `site`는 고객 거점의 VPN 접속 단위(논리)이고 물리 장소는 그 안의 `location`이다. 물리 장소로서의 사이트 = RFC 8299 `location` = TMF674 `GeographicSite` = NetBox Site.

## 위치 계층

```
지역(시·도 / 시·군·구) ─ 사이트 ─ 로케이션(건물·층) ─ 랙 ─ 장비
```

- NetBox는 지역(Region)과 로케이션(Location)을 단계로 고정하지 않고 **중첩 가능한** 하나로 둔다. 건물 없이 층만 있는 곳, 랙 없는 장비가 흔하기 때문이다.

| 항목 | 뜻 | 출처 |

| 위도 · 경도 | WGS 84 십진 도 | RFC 9179 `ellipsoid` › `latitude`, `longitude` |
| 지역 코드 | 시·군·구 코드. 지역 묶음·필터 | 참고: 행정구역 코드 |

- RFC 9179에는 높이(`height`)·속도(`velocity`)도 있다. 선박처럼 **이동하는 사이트**는 고정 좌표가 없어, 장비 GPS로 위치·속도·기록 시각을 계속 갱신한다.

#### 행정구역 코드 체계

| 체계 | 예: 서울 / 부산 / 경기 | 쓰는 곳 |
|---|---|---|
| 행정안전부 법정동 코드(앞 5자리 = 시·군·구) | `11` / `26` / `41` | 주소 API(도로명주소·VWorld·카카오) |

- 두 체계는 시·도 번호가 달라 섞어 쓰려면 대응표가 필요하다.

- 시·군·구 이름(`중구`)은 시·도마다 겹치므로 판정은 코드로.

## 사이트 간 회선

양 끝 장비가 서로 **다른** 사이트에 있는 링크. 사이트 쌍으로 묶어 지도에 선 하나로 그리는 게 보통이다.

| 항목 | 뜻 |
|---|---|
| 양 끝 사이트 | 무방향(A–B = B–A) |
| 링크 수 | 같은 사이트 쌍의 링크 수. 2 이상 = 이중화 |
| 상태 | 묶인 링크 상태를 합친 값 |
| 사용률 | 묶인 링크 트래픽 합 |

- 사업자 망 건너편은 LLDP로 수집되지 않아 수동 링크로 잇는 경우가 많다. 회선이 없는 사이트도 흔하다.

## 노드와의 관계

- 장비는 한 지리적 위치에 있다(ITU-T M.3100) → 노드 : 사이트 = N : 0..1.
- 자동 발견된 장비는 사이트가 비어 있는 게 보통이다(장비가 위치를 알려주지 않는다).

## 수집 방법

장비에서 수집되지 않는다. **사람이 등록**하는 기준 정보다.

| 항목 | 방식 | 1순위 | 대안 | 비고 |
|---|---|---|---|---|
| 이름 · 운용 단계 | 수동 | 관리 화면 등록 / CSV 일괄 등록 | — | |
| 주소 · 우편번호 | 수동 | 주소 검색 API(도로명주소 · VWorld · 카카오) | 직접 입력 | |
| 위도 · 경도 | 둘 다 | 주소 → 좌표 변환(지오코딩) | 지도에서 직접 찍기 | |
| 지역 코드 | 자동 | 주소 API가 돌려주는 법정동 코드 앞 5자리 | 좌표 → 경계 데이터로 계산(역지오코딩) | |
| 노드의 소속 | 수동 | 장비 등록 시 사이트 선택 | SNMP `sysLocation` 문자열로 후보 제안 | `sysLocation`은 자유 문자열이라 자동 확정은 어렵다 |
