[[cs/network/nms/data/topology/index|토폴로지]] 데이터(사이트·노드·인터페이스·링크·서비스)는 그 자체로 민감하다.

## 내부 지도 노출

토폴로지 맵은 공격자가 정찰로 얻고 싶은 정보가 한곳에 모인 것이다.

| 데이터 | 공격자에게 주는 것 |
|---|---|
| 노드 관리 IP, 장비 종류, 모델 | 어디를 공격할지, 어떤 취약점이 맞을지 |
| `sysDescr`(OS·버전) | 알려진 취약점(CVE) 대조 |
| 링크·계층(코어/분배/액세스) | 어디를 끊으면 피해가 큰지(단일 장애점) |
| 사이트 주소·좌표 | 물리적 접근 위치 |
| 서비스·의존성 | DB 같은 핵심 자산의 위치와 경로 |

대응:

- **로그인한 사용자만** 볼 수 있게 하고, 역할별로 보이는 범위를 나눈다(RBAC). 예: 사이트 담당자는 자기 사이트만.
- 내보내기(이미지·CSV·API)는 권한을 따로 둔다. 화면 캡처보다 대량 추출이 더 위험하다.
- 맵 화면·API에 버전 문자열(`sysDescr`) 같은 세부를 꼭 필요한 곳에만 보여 준다.
- YANG 기반 API는 NACM(RFC 8341)으로 노드·경로 단위 접근을 제어할 수 있다. RFC 8345의 Security Considerations도 같은 점(토폴로지 노출, 무단 수정)을 지적한다.

## LLDP 위조

LLDP에는 **인증이 없다.** 아무 장비나 LLDP 프레임을 보내 "나는 코어 스위치의 Gi1/0/1이다"라고 말할 수 있다.

| 위험 | 결과 |
|---|---|
| 가짜 이웃 | 맵에 없는 링크·장비가 생긴다 |
| 가짜 관리 주소(`lldpRemManAddr`) | 이웃 따라가기 발견이 공격자 주소로 접속해 **인증 정보를 보낸다** |
| 정보 노출 | 사용자 포트에서 LLDP를 켜 두면 접속한 PC가 스위치 이름·모델·VLAN을 알 수 있다 |

대응:

- 사용자 단말이 꽂히는 포트(액세스 포트)와 외부 연결 포트에서는 LLDP·CDP 송신을 끈다. 장비끼리 연결된 포트에서만 켠다.
- LLDP로 찾은 링크는 **한쪽 근거만이면 의심**한다(양쪽 확인 여부를 따로 기록: [[cs/network/nms/data/topology/link#방향|링크]]).
- 이웃 정보로 찾은 새 장비는 승인 전까지 인증 정보를 보내지 않는다([[cs/network/nms/security/collection#발견스캔|수집 경로 › 발견]]).

## 수정 권한과 이력

- 수동으로 고치는 값(사이트, 역할, 수동 링크, 맵 좌표)은 **누가 언제 바꿨는지** 남긴다. 잘못된 수동 링크는 장애 분석을 엉뚱한 곳으로 보낸다.
- 노드 승인·무시는 권한을 따로 둔다. 무시(ignore)된 장비는 감시에서 빠지므로 숨기는 데 악용될 수 있다.
- 삭제보다 비활성(보관)을 기본으로 한다. 지워진 장비·링크는 사고 조사 때 필요하다.
