## NIC는 무엇을 보나?

패킷을 받는 카드는 **NIC**(Network Interface Card)다. NAC은 보통 Network Access Control(802.1X 등으로 단말의 망 접속을 허용·차단하는 보안 기능)을 뜻해 다른 것이다.

NIC로는 **물리 포트**(`eth0`)로 들어온다. NIC는 **포트 번호를 모른다.** 포트 번호를 보고 프로세스를 고르는 건 OS 커널이다.

## 수신 과정

| 단계 | 누가 | 보는 것 | 하는 일 |
|---|---|---|---|
| ① 케이블 → 물리 포트 | NIC | 전기·광 신호 (L1) | 비트를 프레임으로 복원 |
| ② 프레임 필터 | NIC | 목적지 **MAC** (L2) | 내 MAC·브로드캐스트·멀티캐스트만 받고 나머지는 버림 (promiscuous 모드면 다 받음) |
| ③ 메모리로 | NIC → RAM | — | DMA로 메모리에 복사, 인터럽트로 CPU에 알림 |
| ④ IP 처리 | 커널 | 목적지 **IP** (L3) | 내 IP면 위로, 아니면 포워딩·버림. Docker의 DNAT(`호스트IP:A` → `컨테이너IP:B`)가 여기서 일어남 |
| ⑤ 소켓 찾기 | 커널 | 목적지 **포트 번호** + TCP/UDP (L4) | 그 포트에서 listen 중인 소켓을 찾음. 없으면 TCP는 RST, UDP는 ICMP port unreachable |
| ⑥ 프로세스 | 앱 | 데이터 (L7) | `recv()`로 읽음 (HTTP 파싱 등) |

계층마다 보는 주소가 다르다.

| 주소 | 질문 | 보는 쪽 |
|---|---|---|
| 물리 포트 (`eth0`) | 어디로 들어왔나 | NIC |
| MAC | 이 카드 앞이 맞나 | NIC |
| IP | 이 장비 앞이 맞나 | 커널 |
| 포트 번호 | 이 장비의 어느 프로세스인가 | 커널 |

Docker 컨테이너라면 물리 포트(`eth0`) → 논리 포트(`docker0` → `veth`) → 포트 번호로 프로세스를 찾아간다. [[cs/network/002_port_kinds|세 가지 포트]]를 차례로 지나는 셈이다.

## NIC가 포트 번호를 보는 경우

요즘 NIC는 성능을 위해 L3·L4 헤더를 일부 본다. 그래도 프로세스를 정하는 건 커널이다.

- RSS(Receive Side Scaling): IP·포트로 해시를 만들어 패킷을 여러 CPU 큐로 나눈다.
- 체크섬 오프로드: TCP/UDP 체크섬을 NIC가 대신 계산한다.
- SmartNIC / DPU: 방화벽·로드밸런싱까지 카드에서 처리한다(예외적인 경우).

## 보낼 때·저장할 때: 객체 → 바이트 → 비트·블록

보내는 쪽은 수신 과정을 거꾸로 밟는다. 그 전에 앱이 한 단계를 더 거친다.

```
네트워크: 객체 ──직렬화(앱)──> 바이트(octet) ──TCP/IP(커널)──> 패킷 ──NIC──> 케이블 위 비트(bps)
디스크:   객체 ──직렬화(앱)──> 바이트 ──파일시스템(커널)──> 디스크 블록(512B / 4KB)
```

| 경계 | 바뀌는 것 | 담당 |
|---|---|---|
| CPU ↔ 메모리 | 바뀌지 않음 (캐시 라인 64B 단위로 오감) | 같은 주소 공간이라 참조를 그대로 따라감 |
| 프로세스 메모리 ↔ 밖 | 객체 ↔ 바이트 | 직렬화 (Java `Serializable`, JSON, Protobuf) |
| 커널 ↔ 디스크 | 바이트 ↔ 블록 | 파일시스템. 앱에는 바이트 API만 보인다 |
| 컴퓨터 ↔ 케이블 | 바이트 ↔ 비트 | NIC |

디스크와 NIC는 같은 구조다. 실제 단위(블록, 비트)는 OS와 하드웨어가 감추고, 앱은 바이트만 다룬다.

- 메모리의 객체는 필드끼리 **메모리 주소(참조)**로 이어져 있다. 이 주소는 그 프로세스 안에서만 의미가 있으므로, 밖으로 보내려면 참조를 따라가 값을 꺼내 바이트 한 줄로 편다. 이게 **직렬화**다.
- 디스크에 저장할 때도 같다. 프로그램을 다시 켜면 객체가 다른 번지에 올라오고, 메모리는 전원이 꺼지면 사라진다. 그래서 주소가 아닌 값을 바이트로 펴서 남긴다.
- 그래서 경계는 "컴퓨터"가 아니라 **프로세스**다. 같은 컴퓨터라도 파일 저장, 다른 프로세스로 전달하려면 직렬화가 필요하다. 같은 JVM 안에서는 참조만 넘기므로 필요 없다.
- 바이트 단위인 이유: 메모리 주소가 가리키는 최소 단위가 1바이트이고, 파일·소켓 같은 OS 입출력 API(`write(fd, buf, len)`)가 모두 바이트 배열을 주고받는다.
- Java `Serializable`은 메서드가 없는 표시용 인터페이스(marker interface)로, "기본 방식으로 직렬화해도 된다"는 허락만 뜻한다. 보안 문제(역직렬화 취약점)와 Java 전용 형식이라는 점 때문에 요즘은 JSON·Protobuf를 더 많이 쓴다.
