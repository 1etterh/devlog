## 디지털 서명이란

디지털 서명은 **비대칭 키(공개키/비밀키)**를 사용하여 데이터의 무결성과 발신자의 신원을 보증하는 기술이다.

종이 문서의 서명이 "이 문서의 내용에 동의한다"는 의미인 것처럼, 디지털 서명은 "이 데이터를 내가 보냈고, 전송 중 변조되지 않았다"는 것을 증명한다.

## 동작 원리

### 서명 생성 (발신자)

```
1. 원본 데이터를 해시 함수(SHA-256 등)로 해시값 생성
2. 해시값을 발신자의 비밀키로 암호화 → 이것이 디지털 서명
3. 원본 데이터 + 디지털 서명을 함께 전송
```

```
[원본 데이터] → SHA-256 → [해시값] → 비밀키로 암호화 → [디지털 서명]
```

### 서명 검증 (수신자)

```
1. 수신한 디지털 서명을 발신자의 공개키로 복호화 → 해시값 A
2. 수신한 원본 데이터를 동일한 해시 함수로 해시 → 해시값 B
3. 해시값 A == 해시값 B → 검증 성공 (변조 없음, 발신자 확인)
```

```
[디지털 서명] → 공개키로 복호화 → [해시값 A]
[원본 데이터] → SHA-256        → [해시값 B]

해시값 A == 해시값 B → 검증 성공
```

## 왜 원본 데이터를 직접 암호화하지 않는가

비대칭 암호화는 대칭 암호화보다 연산 비용이 크다. 원본 데이터가 수 MB~GB일 경우 직접 암호화하면 매우 느리다. 해시값은 항상 고정 길이(SHA-256 = 32 bytes)이므로, 해시값만 암호화하면 서명 생성/검증이 빠르다.

| 방식 | 암호화 대상 | 크기 |
|------|------------|------|
| 직접 암호화 | 원본 데이터 전체 | 수 MB~GB |
| 해시 후 암호화 | 해시값 | 32 bytes (SHA-256) |

## 디지털 서명이 보장하는 것

| 보장 항목 | 설명 |
|----------|------|
| **무결성** (Integrity) | 데이터가 전송 중 변조되지 않았음을 확인 |
| **인증** (Authentication) | 해당 비밀키의 소유자가 서명했음을 확인 |
| **부인 방지** (Non-repudiation) | 서명자가 나중에 "내가 서명하지 않았다"고 부인할 수 없음 |

## SSL 인증서에서의 활용

[[002_SSL인증서, 비밀키 생성|SSL 인증서 생성 과정]]에서 디지털 서명은 두 곳에 사용된다.

### 1. CSR(인증서 서명 요청) 생성 시

```bash
openssl req -new -key private.key -out server.csr
```

신청자의 비밀키로 CSR에 서명하여 공개키 소유권을 증명한다. CA는 이 서명을 검증하여 신청자가 비밀키의 실제 소유자인지 확인한다.

### 2. CA의 인증서 발급 시

CA가 자신의 비밀키로 인증서에 서명한다. 브라우저는 CA의 공개키로 서명을 검증하여 인증서가 신뢰할 수 있는 CA에서 발급되었는지 확인한다.

```
[인증서 내용] → CA의 비밀키로 서명 → [서명된 인증서]

브라우저: CA의 공개키로 서명 검증 → 신뢰 확인
```
