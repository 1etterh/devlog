## 증상

마크다운 task 줄을 다루는 플러그인에서, 다른 문서가 블록 링크(`[[노트#^id]]`)로 가리키던 task를 완료 처리하자 링크가 더 이상 그 줄을 찾지 못했다. 미완료로 되돌리면 다시 정상이었다.

```markdown
- [/] 결제 API 설계 ➕ 2026-10-27 ^sd-abc123          ← 완료 전
- [x] 결제 API 설계 ➕ 2026-10-27 ^sd-abc123 ✅ 2026-10-28   ← 완료 후
```

## 원인

블록 id(`^id`)는 **줄의 맨 끝에 있어야만** 블록 id로 인식된다. 뒤에 다른 글자가 붙으면 그냥 본문 텍스트가 된다.

완료 처리 함수는 "본문 끝에 `✅ 날짜`를 덧붙인다"는 단순한 규칙이었다. 블록 id가 없는 줄에서는 문제가 없었기 때문에, 블록 id를 쓰는 기능(다른 문서에서 task로 링크)이 나중에 추가되면서 숨어 있던 가정이 깨졌다.

```mermaid
flowchart LR
  A["본문 ^id"] -->|"끝에 ✅ 날짜 덧붙임"| B["본문 ^id ✅ 날짜"]
  B --> C["^id가 더 이상 줄 끝이 아님<br/>→ 블록 링크 실패"]
```

## 추적

상태 변경 이력을 기록하는 기능을 만들면서 "같은 task를 블록 id로 식별"하는 테스트를 짰다. `todo → done → todo` 순서로 상태를 바꾸는 케이스에서 완료 직후 줄의 블록 id 위치가 바뀐 것이 보였다.

```text
setTaskStatus('- [/] 결제 ➕ 2026-10-27 ^sd-abc123', 'done')
→ '- [x] 결제 ➕ 2026-10-27 ^sd-abc123 ✅ 2026-10-28'
```

## 수정

줄 끝의 블록 id를 먼저 떼어 내고, 완료 표시를 붙인 다음 다시 맨 끝에 붙인다.

```ts
const BLOCK_ID_RE = /\s\^([A-Za-z0-9-]+)\s*$/;

const cleaned = body.replace(DONE_RE, '').trimEnd();   // 기존 완료 표시 제거
const block = BLOCK_ID_RE.exec(cleaned);
const text = block ? cleaned.slice(0, block.index) : cleaned;
const done = status === 'done' ? ` ✅ ${today}` : '';
return `${head}${statusChar}${mid}${text}${done}${block ? block[0] : ''}`;
```

같은 원칙을 "줄에 태그를 추가하는" 함수에도 적용했다. 새 태그는 날짜 표기와 블록 id **앞**에 삽입한다.

## 정리: 줄 끝 위치가 의미를 갖는 마크다운 요소

| 요소 | 위치 규칙 | 뒤에 글자를 덧붙이면 |
|---|---|---|
| 블록 id `^id` | 줄(블록)의 맨 끝 | 블록 id로 인식되지 않음 → 블록 링크 깨짐 |
| Tasks 플러그인 날짜 표기 (`➕ 📅 ✅`) | 설명 뒤, 블록 id 앞 | 순서가 섞이면 일부 도구가 설명의 일부로 읽음 |
| 체크박스 `[ ]` | 목록 기호 바로 뒤 | — |

**교훈**: 텍스트 줄을 고치는 함수가 "끝에 덧붙인다"를 기본 동작으로 삼으면, 나중에 "끝에 있어야 의미가 있는" 요소가 추가될 때 조용히 깨진다. 줄을 조립할 때는 **꼬리에 붙는 요소들의 순서**(본문 → 날짜 표기 → 블록 id)를 한 곳에서 명시적으로 지키는 편이 안전하다.
