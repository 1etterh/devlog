맵의 점 하나 = **장비** 한 대(스위치·라우터·서버). [[projects/nms/data/topology/interface|인터페이스]]와 [[projects/nms/data/topology/service|서비스]]가 노드에 소속된다.

## 정보

### 논리적 정보

| 항목              | 필수  | 용도                                                                                          | 출처                                |
| --------------- | --- | ------------------------------------------------------------------------------------------- | --------------------------------- |
| 식별자(id)         | O   | 인터페이스가 참조. ECharts `name`에도 id를 넣어 표시명 중복을 피한다                                              | RFC 8345 `node-id`                |
| 이름(name)        | O   | 라벨·툴팁                                                                                       | SNMPv2-MIB `sysName`              |
| 유형(type)        | O   | core / dist / access / server. 범례·모양·크기                                                     | 자체 정의 (참고: Cisco 3계층)             |
| 상태(status)      | O   | UP / WARN / DOWN / UNKNOWN. 색                                                               | 자체 정의 (ping·SNMP 응답)              |
| IP 주소(ip)       | -   | 관리 IP                                                                                       | LLDP-MIB `lldpLocManAddr` 또는 등록 값 |
| 생성 방식(origin)   | O   | MANUAL(사람이 등록) / DISCOVERED(자동 발견)                                                          | 자체 정의 (링크 `origin`과 같은 값)         |
| 승인 상태(approval) | O   | pending(발견됨, 승인 대기) / approved / ignored. 맵 표시·주기 수집은 **approved만** (pending은 발견 시 한 번만 조회) | 자체 정의                             |

#### 유형(type)

망 안에서 맡는 **계층·역할**이다. Cisco 3계층(Core / Distribution / Access)에 서버를 더했다.

| 값        | 이름               | 의미                                                           | 예                 |
| -------- | ---------------- | ------------------------------------------------------------ | ----------------- |
| `core`   | 코어               | 망의 중심. 분배 스위치들을 묶고 다른 사이트·인터넷으로 나간다. 빠른 전달이 목적이라 보통 2대로 이중화  | 코어 L3 스위치, 백본 라우터 |
| `dist`   | 분배(distribution) | 액세스 스위치들을 모아 코어로 올린다. VLAN 간 라우팅·정책을 여기서 건다                  | 층·건물 단위 L3 스위치    |
| `access` | 액세스              | 단말·서버가 직접 꽂히는 맨 아래 스위치                                       | 층·랙 단위 L2 스위치     |
| `server` | 서버               | 망을 구성하지 않고 망에 붙는 호스트. [[projects/nms/data/topology/service|서비스]](컨테이너·프로세스)가 이 위에서 돈다 | 중계 서버, DB 서버      |

방화벽·로드밸런서·무선 AP·라우터처럼 계층이 아니라 **장비 종류**로 구분되는 장비는 지금 유형에 없다. 넣을 때는 계층(`layer`)과 장비 종류(`deviceType`)를 나눠 두는 것을 검토한다.

수집기(장비를 발견·조회하는 서버)는 별도 단위가 아니다. 수집기가 깔린 장비도 유형 `server`인 노드이고, 수집기는 그 노드가 맡은 **역할**이다.

### 물리적 정보

| 항목 | 필수 | 용도 | 출처 |
|---|---|---|---|
| 모델(model) · 제조사(vendor) · 일련번호(serialNo) | - | 상세 표시, 자산 관리 | ENTITY-MIB `entPhysicalModelName` · `entPhysicalMfgName` · `entPhysicalSerialNum` |
| 소속 사이트(siteId) | - | [[projects/nms/data/site|사이트]]. 없으면 지도에 안 나옴("위치 미지정") | 자체 정의 (사람이 지정) |
| 사이트 안 위치(sitePosition) | - | 건물·층·랙 자유 문자열 | 참고값: SNMPv2-MIB `sysLocation` |

## 수집 방법

| 항목                | 방식 | 1순위                               | 대안                                         | 비고                                      |
| ----------------- | --- | --------------------------------- | ------------------------------------------ | --------------------------------------- |
| 식별자(id)           | 자동 | 백엔드가 노드를 만들 때 부여 (수동 등록 또는 자동 발견) | —                                          | 수집 값이 아님. 같은 장비인지는 [중복 판별](#중복-판별)로 가린다 |
| 이름(name)          | 둘 다 | SNMP 폴링 `sysName`                 | 수동 입력                                      |                                         |
| 유형(type)          | 둘 다 | 수동 지정                             | `sysObjectID` · `sysDescr`로 장비 종류 추정       | 망에서의 역할(코어·분배·액세스)은 장비가 알려주지 않는다        |
| 상태(status)        | 자동 | ping + SNMP 응답 여부                 | —                                          | 판정 기준은 자체 정의                            |
| IP 주소(ip)         | 둘 다 | 등록 값(수집 대상 주소)                    | 자동 발견: 이웃 장비의 LLDP `lldpRemManAddr`, 대역 스캔 | 수집하려면 이 주소를 먼저 알아야 한다                   |
| 모델 · 제조사 · 일련번호   | 자동 | SNMP 폴링 ENTITY-MIB                | SSH CLI `show version`                     |                                         |
| 소속 사이트 · 사이트 안 위치 | 수동 | 수동 지정 | `sysLocation` 참고 | [[projects/nms/data/site#수집-방법|사이트 › 수집 방법]] |

필요한 것: 장비 SNMP 활성화와 접속 정보(v2c 커뮤니티 또는 v3 계정 — v3 권장), 수집 서버 → 장비 UDP 161 · ICMP 허용.

### 등록 경로

수동 등록과 자동 발견을 섞는다. 사이트·유형(역할)은 장비가 알려주지 않으므로 자동 발견한 노드도 사람이 승인하며 지정한다.

```
시드 장비 수동 등록 (코어 등)
  → 자동 발견 (아래 방식)
  → 발견됨: approval = pending, origin = DISCOVERED
  → 운영자 승인: 사이트 · 유형 지정 → approved → 수집 시작
```

| 자동 발견 방식 | 어떻게 | 특징 |
|---|---|---|
| 이웃 따라가기 | 시드 장비의 LLDP·CDP 이웃 테이블에서 상대 관리 주소(`lldpRemManAddr`)를 얻고, 그 장비를 다시 조회하며 퍼져 나간다 | 가장 많이 쓴다. 링크도 함께 얻는다 |
| 대역 스캔 | 지정 IP 대역에 ping + SNMP 요청, 응답하는 장비를 후보로 | LLDP 없는 장비도 찾는다. 대역을 알아야 하고 느리다 |
| ARP · MAC 테이블 | 스위치·라우터 테이블에 보이는 주소를 후보로 | 서버·단말까지 보인다. 장비인지 따로 확인 |
| 모르는 장비의 trap | 등록 안 된 주소에서 온 SNMP trap을 후보로 | 보조 수단 |

자동 발견에도 SNMP 접속 정보가 필요하다. 미리 등록한 접속 정보 목록을 차례로 시도한다.

### 중복 판별

자동 발견한 장비가 이미 있는 노드인지 아래 순서로 비교한다. IP만 보면 IP가 바뀐 장비가 두 개로 잡힌다.

1. 장비 고유값: LLDP `lldpLocChassisId`, ENTITY-MIB `entPhysicalSerialNum`
2. `sysName`
3. 관리 IP
