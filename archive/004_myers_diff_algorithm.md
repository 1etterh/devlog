**Q**: Myers 알고리즘은 무엇인가? Git diff가 기본으로 쓴다는데 어떻게 동작하는가?

**A**: 두 텍스트 시퀀스 사이의 **최소 편집 거리(SES, Shortest Edit Script)** 를 찾는 diff 알고리즘. Eugene W. Myers, 1986년 논문 *"An O(ND) Difference Algorithm and Its Variations"*. Git/GNU diff/Mercurial 등 대부분 도구의 기본값.

## 핵심 아이디어: edit graph 최단 경로

- 노드: 두 시퀀스 A(N줄), B(M줄)의 위치 `(i, j)`
- 간선:
  - 대각선 = 같은 줄 매칭 (cost 0)
  - 오른쪽 = A에서 한 줄 삭제 (cost 1)
  - 아래쪽 = B에서 한 줄 삽입 (cost 1)
- `(0,0) → (N,M)`까지 최소 비용 경로를 BFS로 탐색하면 그 경로가 곧 diff

이는 **LCS(최장 공통 부분수열)** 찾기와 동치이고, LCS의 보수가 SES이다.

## 복잡도

- 시간: **O((N+M)·D)** — D = 편집 횟수
- 공간: 분할정복 변형으로 O(N+M)까지 줄임
- 의미: 변경이 적을수록(D가 작을수록) 매우 빠름. 코드 diff처럼 작은 변경에 특히 효율적

## Git의 diff 알고리즘 비교

`git diff --diff-algorithm=<name>` 또는 `diff.algorithm` 설정.

| 알고리즘 | 특징 | 적합한 상황 |
|---|---|---|
| myers (기본) | 최소 편집 거리 우선 | 일반 텍스트 |
| minimal | myers 변형, 더 작은 diff 추구 | 짧은 diff가 필요할 때 |
| patience | 고유한 anchor 줄을 먼저 매칭 | 블록 이동·복사 |
| histogram | patience 발전형, 빈도 기반 | 코드 변경 (실무 권장) |

## 한계

Myers는 “편집 횟수 최소화”만 추구하므로 사람이 보기에 어색한 매칭이 나올 수 있다. 함수 블록 두 개가 교체된 경우 줄을 뒤섞어 매칭하기도 하는데, 이런 상황에서는 `histogram`이 더 깔끔하다. 그래서 많은 팀이 `git config --global diff.algorithm histogram`을 사용한다.

## 한 줄 정리

“두 파일을 비교해 가장 짧은 삽입·삭제 시퀀스를 찾는 알고리즘”이며, 그 시퀀스가 곧 우리가 보는 `git diff`의 `+`/`-` 줄이다.

## 작은 예시로 그려보기: `ABC` → `AXC`

직관적으로 “B 삭제 + X 삽입” 2번이면 된다. Myers는 이걸 2D 격자 위 최단 경로 문제로 본다.

### Edit graph

```
              A      B      C       ← 원본 A = "ABC" (가로축)
        ┌─────┬──────┬──────┬─────┐
   start│(0,0)│ →    │ →    │ →   │
        │  ╲  │      │      │     │  ╲ : 양쪽 글자가 같을 때만
        │   ╲ │      │      │     │       이동 가능 (cost 0, match)
     A  │     │(1,1) │ →    │ →   │  → : 가로 = 원본에서 글자 삭제
        │     │      │      │     │       (cost 1, delete)
        │     │  ↓   │      │     │  ↓ : 세로 = 새 문자열에 글자 삽입
     X  │     │(1,2) │(2,2) │ →   │       (cost 1, insert)
        │     │      │  ╲   │     │
        │     │      │   ╲  │     │
     C  │     │      │      │(3,3)│ ← end
        └─────┴──────┴──────┴─────┘
   ↑ 새 문자열 B = "AXC" (세로축)
```

가로축은 원본 `ABC`, 세로축은 목표 `AXC`. `(0,0)`에서 `(3,3)`까지 최소 비용 경로를 찾는다.

대각선 매치 검증:
- `(0,0) → (1,1)`: 가로 1번째 `A`, 세로 1번째 `A` → 매치
- `(2,1) → (2,2)`: 가로 2번째 `B`, 세로 2번째 `X` → 다름, 매치 불가
- `(2,2) → (3,3)`: 가로 3번째 `C`, 세로 3번째 `C` → 매치

### 경로 추적

| 단계 | 이동 | 의미 | 누적 비용 |
|---|---|---|---|
| `(0,0) → (1,1)` | 대각선 ╲ | A=A 매치 | 0 |
| `(1,1) → (2,1)` | 오른쪽 → | B 삭제 | 1 |
| `(2,1) → (2,2)` | 아래 ↓ | X 삽입 | 2 |
| `(2,2) → (3,3)` | 대각선 ╲ | C=C 매치 | 2 |

D = 2. 이 경로가 그대로 diff 출력이 된다.

```diff
 A    ← 매치(대각선)
-B    ← 삭제(오른쪽)
+X    ← 삽입(아래)
 C    ← 매치(대각선)
```

### BFS로 푸는 이유

대각선이 cost 0, 가로/세로가 cost 1인 가중치 그래프지만, Myers는 **편집 횟수 D를 외부 파라미터로 두고 D=0,1,2,…를 늘려가며 도달 가능한 가장 먼 대각선을 추적**한다. 그래서 시간 복잡도가 `O((N+M)·D)` — 변경이 적을수록 매우 빠른 핵심 이유다.
