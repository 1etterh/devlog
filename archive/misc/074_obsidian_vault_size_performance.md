**결론**: 파일·폴더 **개수만으로는** 웬만해서 안 느려진다. 느려지는 건 개수보다 **무엇을 얼마나 하는 파일이 많은지**(첨부 용량, 큰 파일, 플러그인, 그래프)다. 수천~1만 개 노트 정도는 흔히 문제없이 쓰고, 수만 개부터 시작·검색에서 체감이 생기기 시작한다.

## Obsidian이 파일을 다루는 방식

```mermaid
flowchart LR
  A["vault 폴더"] -->|"시작 시 전체 스캔"| B["파일 목록<br/>(이름·경로·수정시각)"]
  B -->|".md만 파싱"| C["메타데이터 캐시<br/>(링크·태그·헤더·frontmatter)"]
  C --> D["백링크 / 검색 / 그래프 / 퀵 스위처"]
  B -->|"이후 변경만 감시"| E["파일 감시자"]
```

- 시작할 때 vault 전체를 훑고, `.md`는 링크·태그·헤더를 뽑아 **캐시(IndexedDB)**에 저장한다. 두 번째 실행부터는 바뀐 파일만 다시 읽는다.
- 그래서 **처음 열 때·캐시를 지웠을 때**가 가장 느리고, 평소에는 개수 영향이 작다.
- 폴더 깊이·개수 자체는 거의 비용이 없다. 탐색기 트리를 그리는 비용 정도.

## 무엇이 실제로 느리게 만드나

| 원인 | 왜 느려지나 | 대처 |
|---|---|---|
| 노트 수 (수만 개 이상) | 시작 스캔·캐시 재구축, 전체 검색 시간 증가 | 안 쓰는 노트를 vault 밖으로 보관, vault 분리 |
| 첨부 용량 (이미지·PDF·영상) | 스캔 대상이 커지고, 동기화(iCloud 등) 부하 | 첨부 폴더 정리, 큰 파일은 vault 밖 링크 |
| 아주 큰 단일 노트 (수 MB, 긴 표) | 편집기·라이브 프리뷰 렌더링이 무거움 | 노트 분할 |
| 플러그인 | 시작 시 로드, 일부는 모든 파일을 따로 인덱싱(Dataview, 검색·태스크류, Excalidraw 등) | 안 쓰는 플러그인 끄기, 시작 시간은 설정 › 커뮤니티 플러그인에서 확인 |
| 그래프 뷰 | 노드·링크가 많으면 물리 시뮬레이션이 무거움 | 필터로 범위 줄이기 |
| 동기화 폴더 (iCloud Drive 등) | 파일을 내려받는 중이면 열기·스캔이 지연 | 기기에 항상 보관 설정 |
| `.git` 등 숨김 폴더 | 점(.)으로 시작하는 폴더는 Obsidian이 무시 → 영향 거의 없음 | — |

## 개수별 체감 (일반적인 경향)

| 규모 | 체감 |
|---|---|
| ~1,000개 | 차이 없음 |
| ~10,000개 | 대부분 문제없음. 첫 인덱싱이 수십 초 걸릴 수 있음 |
| 수만 개 이상 | 시작·전체 검색·그래프에서 느려짐 체감, 플러그인 영향 커짐 |

(기기 성능·플러그인 구성에 따라 크게 달라지는 경향치다.)

## 참고: 이 vault의 경우 (2026-11-19 측정)

- 노트(.md) 115개, 전체 파일 173개, 폴더 51개 → 개수로는 전혀 문제없는 규모.
- vault 186MB 중 166MB가 `.obsidian/plugins` (플러그인 코드, 특히 Excalidraw 같은 큰 플러그인). 느리게 느껴진다면 노트 수보다 **플러그인 로딩**을 먼저 의심하는 게 맞다.

## "설정 › 파일 및 링크 › 제외할 파일"은?

검색·그래프·퀵 스위처 결과에서 빼 주는 옵션이다. 인덱싱 자체를 완전히 막는 건 아니라서 성능 개선 효과는 제한적이다. 정말 무거운 폴더는 vault 밖으로 빼는 게 확실하다.
